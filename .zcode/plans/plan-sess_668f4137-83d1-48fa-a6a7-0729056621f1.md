## 二、核心文件合并策略（逐文件说明）

| 文件 | 策略 | 来源 |
|---|---|---|
| `base/base_task.py` | 用 main 版 | step/reset/get_observations 全被各 env override（死 stub），main 版不引用 dreamwaq 专有字段，对 main 特技任务最安全 |
| `base/base_config.py` | 用 dreamwaq 版 | 3 分支一致，仅许可证头差异 |
| `base/legged_robot.py` | 用 dreamwaq 版 | 死代码（无任何继承/实例化），保留 dreamwaq 版接口约定 |
| `base/legged_robot_config.py` | 用 dreamwaq 版 | go2 实参基底，含 safety 类，3 分支一致。**核对 main 7 个 PPO config 的训练超参是否被基类默认值污染（learning_rate/max_iterations），必要时在子类显式补上** |
| `utils/task_registry.py` | 用 amp_cts 版（动态 eval 调度） | `runner = eval(train_cfg_dict["runner_class_name"])(...)`，兼容所有 runner。import 全部 5 个 runner 类 |
| `utils/helpers.py` | 取并集 | main 基底（get_load_path 用 mtime 排序、get_args task="go2"）+ DWAQ 导出器 + CTS 导出器。丢弃 amp_dreamwaq 的死代码 jit_actor/jit_encoder |
| `utils/math.py` | 取并集 | main 基底（含 6 个独有函数）+ dreamwaq 的 get_scale_shift |
| `utils/terrain.py` | 取并集 | dreamwaq 版（含 rough_terrain）+ `__init__(self, cfg, num_robots=None)` 兼容 main 调用 |
| `utils/__init__.py` | 更新导出 | 补 export_policy_as_dwaq、export_policy_as_cts |
| `rsl_rl/utils/utils.py` | 用 amp_cts 版 | main=dreamwaq 一组，amp_dw=amp_cts 一组，取 amp_cts（最新） |
| `setup.py` | 用 main 版 | 包名 my_unitree_go2_gym |

## 六、关键风险与注意事项

1. **legged_robot_config.py 换基底的影响**：main 7 个特技任务的 Cfg 如果没显式设 learning_rate/max_iterations，会从 main 基类的 `1e-3/1500` 变成 dreamwaq 基类的 `1e-5/10000`。需逐一核对，必要时在子类显式补上。
2. **amp_cts 的死代码**：`go2_trot/GO2_Stairs.py` 未注册，与 dreamwaq 同源，迁移时不引入。
3. **experiment_name 冲突**：amp_cts 里 go2_cts 和 go2_amp_cts 的 experiment_name 都是 `go2_cts`，日志会混。融合时改 go2_amp_cts 的为 `go2_amp_cts`。
4. **datasets 相对路径**：AMP 配置用 `glob.glob('datasets/mocap_motions_go2/*')` 相对路径，依赖从仓库根运行。保持不变。
5. **train.py 的硬编码 hack**：`legged_gym.__file__ = "/home/zju/dreamwaq/..."` 必须删除。
